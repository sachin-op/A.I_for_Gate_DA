Logical Reasoning

Reasoning GATE DA 📖 ~18 min read

Logical Reasoning is the process of applying inference rules to a Knowledge Base to derive new facts. It is the engine that makes a logic-based AI system intelligent — instead of storing every possible fact, the agent stores a compact set of rules and derives everything else automatically.

Core Goal: Given KB (what we know) and a query α (what we want to know), determine whether KB |= α — does the knowledge base entail α?

1. Inference Rules

Inference rules are patterns of valid reasoning. If the premises match facts in the KB, the conclusion can be added as a new fact.

1.1 Modus Ponens

The most fundamental and commonly used inference rule.

P → Q  ,  P
──────────────────
∴  Q

In English: If "P implies Q" is true, and P is true, then Q must be true.

Example:

  KB:
  ├── It is raining              (P)
  └── If it rains → roads wet    (P → Q)

  Derived: Roads are wet         (Q) ✓

1.2 Modus Tollens

P → Q  ,  ¬Q
──────────────────
∴  ¬P

In English: If "P implies Q" is true and Q is false, then P must be false.

Example:

  KB:
  ├── If it rains → roads wet    (P → Q)
  └── Roads are NOT wet          (¬Q)

  Derived: It is NOT raining     (¬P) ✓

1.3 Hypothetical Syllogism (Transitivity)

P → Q  ,  Q → R
──────────────────────
∴  P → R

In English: If P implies Q and Q implies R, then P implies R.

Example:

  If it rains → roads wet    (P → Q)
  If roads wet → accidents   (Q → R)
  ─────────────────────────────────
  If it rains → accidents    (P → R) ✓

1.4 Disjunctive Syllogism

P ∨ Q  ,  ¬P
──────────────────
∴  Q

In English: If P or Q is true and P is false, then Q must be true.

1.5 And-Introduction

P  ,  Q
──────────
∴  P ∧ Q

1.6 And-Elimination

P ∧ Q
──────
∴  P  (or Q)

2. Resolution

Resolution is a powerful inference rule used in automated theorem proving. It is the basis of the resolution algorithm — a complete method for propositional and first-order logic.

Resolution Rule

P ∨ Q  ,  ¬P ∨ R
───────────────────────
∴  Q ∨ R

If P is true → from ¬P ∨ R, we get R.
If P is false → from P ∨ Q, we get Q.
Either way: Q ∨ R must be true.

Special Case — Unit Resolution

P ∨ Q  ,  ¬P
────────────────────
∴  Q

This is the same as Disjunctive Syllogism — resolution applied to a unit clause.

Resolution for Theorem Proving

To prove that KB entails α using resolution, we use proof by refutation (contradiction):

  1. Assume the negation of α is true: add ¬α to KB
  2. Convert everything to Conjunctive Normal Form (CNF)
  3. Apply resolution repeatedly to produce new clauses
  4. If we derive the empty clause (□) → contradiction found
  5. Contradiction means ¬α cannot be true → therefore α must be true
Why CNF? Conjunctive Normal Form means the formula is a conjunction (AND) of clauses, where each clause is a disjunction (OR) of literals. Resolution only works on clauses in this form.

Example CNF: (P ∨ Q) ∧ (¬P ∨ R) ∧ (¬Q ∨ S)

Resolution Example

Prove: KB |= Q

  KB:
  ├── P ∨ Q
  └── ¬P

  Step 1: Add ¬Q to KB (negation of what we want to prove)
  KB now: { P ∨ Q,  ¬P,  ¬Q }

  Step 2: Resolve P ∨ Q with ¬P:
          P ∨ Q , ¬P  →  Q

  Step 3: Resolve Q with ¬Q:
          Q , ¬Q  →  □ (empty clause — contradiction!)

  ∴ KB |= Q  ✓

3. Forward Chaining

Forward Chaining starts from the known facts in the KB and applies inference rules to derive new facts, repeating until the goal is reached or no new facts can be derived.

Direction

Facts → Rules → New Facts → Rules → ... → Goal

Algorithm

  1. Start with all known facts in the KB.
  2. Find any rule whose premises are all satisfied by known facts.
  3. Add the rule's conclusion as a new fact.
  4. Repeat until the goal is derived or no new facts can be added.

Example

  KB (Rules):
  ├── R1: A ∧ B → C
  ├── R2: C ∧ D → E
  └── R3: E → F

  Known Facts: A, B, D

  Goal: Prove F

  Step 1: A and B are known → R1 fires → derive C
  Step 2: C and D are known → R2 fires → derive E
  Step 3: E is known → R3 fires → derive F ✓

  Goal F is reached!

Properties of Forward Chaining

PropertyValueExplanation
Sound? ✓ Yes Only derives facts that logically follow
Complete? ✓ Yes Will find the goal if it is entailed by the KB
Direction Data-driven Starts from facts, works toward goal
Best for Known facts, unknown goal When you have lots of facts and want to see what follows
Used in Expert Systems, Production Systems Medical diagnosis, business rule engines

4. Backward Chaining

Backward Chaining starts from the goal and works backward — finding rules that could prove the goal, then checking if their premises are satisfied (or can be proven recursively).

Direction

Goal → Rules → Sub-Goals → Rules → ... → Known Facts

Algorithm

  1. Start with the goal to be proved.
  2. Find a rule whose conclusion matches the goal.
  3. Set the rule's premises as new sub-goals.
  4. Recursively prove each sub-goal.
  5. If all sub-goals are satisfied by known facts → goal is proved.

Example

  KB (Rules):
  ├── R1: A ∧ B → C
  ├── R2: C ∧ D → E
  └── R3: E → F

  Known Facts: A, B, D

  Goal: Prove F

  Step 1: Goal = F. Which rule concludes F? → R3: E → F
          New sub-goal: E

  Step 2: Sub-goal = E. Which rule concludes E? → R2: C ∧ D → E
          New sub-goals: C and D

  Step 3: Sub-goal = D. D is a known fact! ✓
          Sub-goal = C. Which rule concludes C? → R1: A ∧ B → C
          New sub-goals: A and B

  Step 4: A is a known fact! ✓
          B is a known fact! ✓

  All sub-goals satisfied → F is proved! ✓

Properties of Backward Chaining

PropertyValueExplanation
Sound? ✓ Yes Only proves goals that are actually entailed
Complete? ✓ Yes Will find a proof if one exists
Direction Goal-driven Starts from goal, works toward facts
Best for Specific query/goal When you have a specific question to answer
Used in Prolog, Query Systems Logic programming, question answering

5. Forward vs Backward Chaining

PropertyForward ChainingBackward Chaining
Direction Facts → Goal Goal → Facts
Driven by Data (facts) Goal (query)
Explores All possible conclusions from facts Only what is needed to prove the goal
Efficiency May derive irrelevant facts More focused — avoids irrelevant derivations
Best when Goal is unknown, many facts available Specific goal to prove, fewer facts
Sound? ✓ Yes ✓ Yes
Complete? ✓ Yes ✓ Yes
Used in Expert systems, rule engines Prolog, query answering systems
Analogy: Forward chaining is like a detective who collects all available clues and sees what conclusion they point to. Backward chaining is like a detective who starts with a suspect and looks for evidence that supports or refutes that specific theory.

GATE Tips

  • Modus Ponens: P → Q, P ⇒ Q. Most important inference rule.
  • Modus Tollens: P → Q, ¬Q ⇒ ¬P. Contrapositive reasoning.
  • Resolution: P ∨ Q, ¬P ∨ R ⇒ Q ∨ R. Key for theorem proving.
  • Resolution uses proof by refutation — add ¬α and derive a contradiction (empty clause □).
  • Forward Chaining = data-driven = starts from facts.
  • Backward Chaining = goal-driven = starts from query.
  • Both Forward and Backward Chaining are sound and complete.
  • CNF (Conjunctive Normal Form) is required before applying Resolution.
  • Empty clause □ derived during Resolution = contradiction = goal is proved.
  • In GATE, trace Forward/Backward Chaining step by step — marks are given for each derivation step.
📝  Practice Questions

Q1 Which inference rule has the form: P → Q, P ⇒ Q?

  1. Modus Tollens
  2. Resolution
  3. Modus Ponens
  4. Hypothetical Syllogism
Show Answer

Answer: C — Modus Ponens

If the implication P → Q is true and the premise P is true, then Q must be true.

Q2 Forward Chaining is called "data-driven" because:

  1. It uses a database to store facts
  2. It starts from known facts and derives new ones toward the goal
  3. It starts from the goal and works backward
  4. It only works with numerical data
Show Answer

Answer: B — Starts from known facts and derives toward the goal

Forward chaining is driven by the available data (facts), not the goal.

Q3 In Resolution-based theorem proving, how is a goal α proved?

  1. Add α to KB and derive True
  2. Add ¬α to KB and derive the empty clause (contradiction)
  3. Remove α from KB and check if KB is consistent
  4. Apply Modus Ponens directly to α
Show Answer

Answer: B — Add ¬α and derive the empty clause

This is proof by refutation. If assuming ¬α leads to contradiction (□), then α must be true.

Q4 Backward Chaining is best suited when:

  1. There are many facts and the goal is unknown
  2. There is a specific goal to prove and we want to find supporting facts
  3. The KB has no rules, only facts
  4. We want to derive all possible conclusions
Show Answer

Answer: B — Specific goal to prove

Backward chaining focuses only on what is needed to prove the specific goal — avoiding irrelevant derivations.

Q5 Which of the following is the Resolution rule?

  1. P → Q, P ⇒ Q
  2. P → Q, ¬Q ⇒ ¬P
  3. P ∨ Q, ¬P ∨ R ⇒ Q ∨ R
  4. P ∧ Q ⇒ P
Show Answer

Answer: C — P ∨ Q, ¬P ∨ R ⇒ Q ∨ R

Resolution resolves two clauses that contain complementary literals (P and ¬P) to produce a new clause.

Q6 Both Forward and Backward Chaining are:

  1. Sound but not complete
  2. Complete but not sound
  3. Neither sound nor complete
  4. Both sound and complete
Show Answer

Answer: D — Both sound and complete

Both algorithms are sound (only derive true facts) and complete (will find the goal if it is entailed).

Q7 Given KB: {A, A → B, B → C}. Using Forward Chaining, what is derived?

  1. Only B
  2. B and C
  3. Only C
  4. A, B, and C
Show Answer

Answer: B — B and C

Step 1: A is known, A → B fires → derive B. Step 2: B is known, B → C fires → derive C. A was already known so only B and C are newly derived.

Q8 What does deriving the empty clause (□) in Resolution mean?

  1. The goal is false
  2. The KB is incomplete
  3. A contradiction was found — the goal is proved
  4. Resolution has failed
Show Answer

Answer: C — A contradiction was found, the goal is proved

The empty clause means we derived False from the KB + ¬α, which means ¬α cannot hold — so α must be true.
