Bidirectional Search

Uninformed Search GATE DA 📖 ~10 min read

Bidirectional Search is a search strategy that runs two simultaneous searches — one forward from the initial state and one backward from the goal state — and stops when the two frontiers meet in the middle.

Core Idea: Instead of one search exploring bd nodes, run two searches each exploring only bd/2 nodes. Meeting in the middle gives a dramatic reduction in nodes explored.

Why Bidirectional Search?

The key motivation is the exponential reduction in nodes explored. Consider BFS with branching factor b = 10 and goal at depth d = 6:

AlgorithmNodes ExploredCalculation
BFS (one direction) 1,111,111 bd = 106 ≈ 1 million
Bidirectional BFS 2,222 2 × bd/2 = 2 × 103 ≈ 2 thousand

Bidirectional search explores roughly 500× fewer nodes in this example. The deeper the goal, the more dramatic the saving.

How Bidirectional Search Works

  1. Start Search 1 (forward) from the initial state.
  2. Start Search 2 (backward) from the goal state.
  3. Both searches expand their frontiers simultaneously, one level at a time.
  4. At each step, check if the frontier of one search intersects with the explored set of the other.
  5. When they meet → combine the two partial paths to form the full solution.

Data Structure Used

Typically uses two BFS queues — one for each direction. Can also use DFS or UCS in each direction depending on the variant.

Key Condition

The search terminates when a node is found that is in both frontiers (or one frontier intersects the explored set of the other).

Visual Intuition

  Forward search         Backward search
  from START             from GOAL
       ↓                      ↑
  [ S ]→→→→→[ ... ]    [ ... ]←←←←[ G ]
                  ↘        ↙
                  [ MEET ] ← intersection point

Think of two people trying to find each other in a city. Instead of one person searching everywhere, both walk toward each other — they meet in half the distance.

Properties of Bidirectional Search

PropertyValueExplanation
Complete? ✓ Yes* Complete if both directions use BFS
Optimal? ✓ Yes* Optimal if both directions use BFS with equal step costs
Time Complexity O(bd/2) Each direction explores half the depth
Space Complexity O(bd/2) Both frontiers stored simultaneously

* Depends on the search strategy used in each direction.

Complexity Analysis

With branching factor b and goal at depth d:

AlgorithmTimeSpace
BFSO(bd)O(bd)
Bidirectional BFSO(bd/2)O(bd/2)
Mathematical Insight: bd/2 + bd/2 = 2·bd/2 which is far less than bd for large b and d. For b=10, d=10: BFS explores 1010 = 10 billion nodes, Bidirectional explores 2 × 105 = 200,000 nodes.

Requirements for Bidirectional Search

Bidirectional search has some important prerequisites that must be satisfied:

RequirementWhy It's Needed
Goal state must be known The backward search starts from the goal — so the goal must be a single explicit state, not a general condition
Operators must be reversible The backward search needs to apply operators in reverse — not always possible
Predecessor function must exist Must be able to generate parent nodes from a child (reverse of successor function)
Efficient intersection check Need a fast way to check if frontiers overlap — typically a hash set

Variants of Bidirectional Search

VariantForwardBackwardNotes
Bidirectional BFS BFS BFS Most common. Complete and optimal (equal costs).
Bidirectional UCS UCS UCS Optimal for weighted graphs. More complex stopping condition.
Bidirectional A* A* A* Informed variant. Requires careful handling to guarantee optimality.

When to Use Bidirectional Search

SituationUse Bidirectional?

Advantages & Disadvantages

✅ Advantages

  • Dramatically reduces time and space — O(bd/2) vs O(bd)
  • Complete and optimal when using BFS in both directions
  • Very effective for problems with a single well-defined goal

❌ Disadvantages

  • Goal state must be explicitly known in advance
  • Operators must be reversible — not always possible
  • More complex to implement — need intersection detection
  • Both frontiers require memory — worse than IDDFS for memory
  • Stopping condition is tricky — must ensure the path found is truly optimal

GATE Tips

  • Time and space complexity is O(bd/2) — the key fact to remember.
  • Two conditions required: goal must be known + operators reversible.
  • Bidirectional BFS is complete and optimal for equal step costs.
  • The meeting point is in the middle at depth d/2 — not always exactly half.
  • For GATE MCQs: compare bd (BFS) vs 2·bd/2 (Bidirectional) — bidirectional is always smaller for b,d > 1.
  • Bidirectional A* is the informed version — mentioned often in GATE context.
📝  Practice Questions

Q1 What is the time complexity of Bidirectional BFS?

  1. O(bd)
  2. O(bd/2)
  3. O(b · d)
  4. O(2d)
Show Answer

Answer: B — O(bd/2)

Each direction searches to depth d/2, so total nodes = 2 × bd/2 = O(bd/2).

Q2 Which condition is NOT required for Bidirectional Search?

  1. The goal state must be known explicitly
  2. Operators must be reversible
  3. The branching factor must be less than 10
  4. A predecessor function must exist
Show Answer

Answer: C — Branching factor restriction

There is no restriction on the branching factor. The other three are genuine requirements.

Q3 For b=10, d=6, how many nodes does Bidirectional BFS explore compared to BFS?

  1. Same number
  2. Half as many
  3. About 500 times fewer
  4. About 1000 times fewer
Show Answer

Answer: C — About 500 times fewer

BFS: bd = 106 = 1,000,000. Bidirectional: 2 × 103 = 2,000. Ratio ≈ 500.

Q4 Bidirectional search is NOT suitable when:

  1. The graph is very large
  2. The goal is a general condition rather than an explicit state
  3. The branching factor is large
  4. The start and goal are far apart
Show Answer

Answer: B — Goal is a general condition

Backward search requires starting from an explicit goal state. A vague goal condition makes backward search impossible.

Q5 Bidirectional search terminates when:

  1. The forward search reaches the goal
  2. The backward search reaches the start
  3. The two frontiers intersect (meet in the middle)
  4. Both queues become empty
Show Answer

Answer: C — Two frontiers intersect

The algorithm stops when a node appears in both frontiers, meaning a complete path from start to goal has been found.

Q6 Which of the following is true about Bidirectional BFS?

  1. It uses less memory than IDDFS
  2. It is complete and optimal for equal step costs
  3. It does not require the goal state to be known
  4. It always explores exactly d/2 levels in each direction
Show Answer

Answer: B — Complete and optimal for equal step costs

A is false (IDDFS uses O(b·d), bidirectional uses O(bd/2) — bidirectional uses more memory). C is false (goal must be known). D is false (meeting point is approximately d/2 but not always exact).
