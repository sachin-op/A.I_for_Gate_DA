Adversarial Search Algorithms

Search GATE DA 📖 ~15 min read

Adversarial Search is used in competitive environments — typically two-player games — where one player tries to maximize their advantage while the opponent tries to minimize it. Unlike regular search where we control all actions, here an opponent works against us.

Core Idea: We cannot just plan our own moves — we must also anticipate and account for every possible move the opponent might make. The goal is to find the optimal strategy assuming the opponent also plays optimally.

Game Formulation

A two-player zero-sum game is defined by:

ComponentMeaningExample (Chess)
Initial State Starting configuration of the board Standard chess starting position
Players Two players — MAX and MIN White (MAX) and Black (MIN)
Actions Legal moves available at each state All valid chess moves
Result New state after an action is applied Board position after a move
Terminal Test Is the game over? Checkmate, stalemate, draw
Utility Function Score at terminal states +1 (win), 0 (draw), -1 (loss)

Zero-Sum Game

In a zero-sum game, one player's gain is exactly the other player's loss. The total payoff always sums to zero.

  • MAX wants to maximize the utility value
  • MIN wants to minimize the utility value
  • Examples: Chess, Tic-Tac-Toe, Go, Checkers

Game Tree

A game tree represents all possible states of a game. Each node is a game state and each edge is a move. The tree alternates between MAX nodes (our turn) and MIN nodes (opponent's turn). 

                    MAX's turn
                   [Root: 3]
                  /          \
          MIN's turn        MIN's turn
           [3]                [2]
          /   \              /   \
        [3]   [5]          [2]   [9]
    (terminal) (terminal) (terminal) (terminal)

The numbers at terminal nodes are utility values. MAX picks the child with the highest value, MIN picks the lowest.

1. Minimax Algorithm

The Minimax algorithm computes the optimal move for MAX assuming MIN plays optimally. It performs a complete depth-first search of the game tree.

How Minimax Works

  1. Build the complete game tree down to terminal states.
  2. Assign utility values to all terminal states.
  3. Back up values from terminal nodes to the root:
    • At a MAX node → take the maximum of children's values
    • At a MIN node → take the minimum of children's values
  4. The root's backed-up value is the minimax value — MAX chooses the move leading to it.

Minimax Formula

  MINIMAX(s) =
    UTILITY(s)                          if s is terminal
    max { MINIMAX(result(s,a)) }        if player(s) = MAX
    min { MINIMAX(result(s,a)) }        if player(s) = MIN

Example — Step by Step

                       MAX
                      [ ? ]
                   /         \
                MIN            MIN
               [ ? ]          [ ? ]
              /     \        /     \
            [3]     [5]    [2]     [9]

  Step 1: Terminal values → 3, 5, 2, 9
  Step 2: MIN nodes:
          Left MIN  = min(3, 5) = 3
          Right MIN = min(2, 9) = 2
  Step 3: MAX node:
          Root MAX  = max(3, 2) = 3

  ✓ Optimal move: go LEFT (value = 3)

Properties of Minimax

PropertyValueExplanation
Complete? ✓ Yes Complete if game tree is finite
Optimal? ✓ Yes Optimal against a perfect opponent
Time Complexity O(bm) b = branching factor, m = max depth
Space Complexity O(b·m) DFS — only stores current path
Problem with Minimax: For games like Chess (b ≈ 35, m ≈ 100), the number of nodes is 35100 — completely infeasible. This is why Alpha-Beta Pruning is needed.

2. Alpha-Beta Pruning

Alpha-Beta Pruning is an optimization of Minimax that prunes branches of the game tree that cannot possibly affect the final decision. It returns the exact same result as Minimax but explores far fewer nodes.

Two Key Parameters

ParameterMaintained byMeaning
α (Alpha) MAX player Best value MAX can guarantee so far (starts at -∞)
β (Beta) MIN player Best value MIN can guarantee so far (starts at +∞)

Pruning Conditions

  • At a MIN node: If the current value ≤ α → prune (MAX already has a better option elsewhere)
  • At a MAX node: If the current value ≥ β → prune (MIN already has a better option elsewhere)

Pruning Rule

  Prune when:  α ≥ β

  At MIN node: if value ≤ α → stop (prune remaining children)
  At MAX node: if value ≥ β → stop (prune remaining children)

Alpha-Beta Example

                        MAX [α=-∞, β=+∞]
                       /                \
            MIN [α=-∞, β=+∞]        MIN [α=3, β=+∞]
            /        \               /        \
         [3]         [5]          [2]         [PRUNED ✂]
     α updated=3                β=2 < α=3 → PRUNE!

  Left subtree: MIN sees 3,5 → returns 3. α = 3.
  Right subtree: MIN sees 2. Since 2 < α(3) → prune remaining.
  Root MAX: max(3, 2) = 3. Same answer as Minimax!

How Much Does Alpha-Beta Save?

Move OrderingNodes ExploredEffective Branching Factor
Worst case (worst ordering) O(bm) Same as Minimax — no savings
Average case (random ordering) O(b3m/4) Significant reduction
Best case (perfect ordering) O(bm/2) Search depth effectively doubles!
Best Case Insight: With perfect move ordering, Alpha-Beta can search twice as deep as Minimax in the same time. For Chess, this means going from depth 8 to depth 16 — a massive improvement.

Properties of Alpha-Beta Pruning

PropertyValueExplanation
Complete? ✓ Yes Same as Minimax
Optimal? ✓ Yes Returns exact same result as Minimax
Time (best case) O(bm/2) Perfect move ordering
Time (worst case) O(bm) No pruning happens
Space O(b·m) Same as Minimax

3. Evaluation Functions

In real games like Chess, we cannot search all the way to terminal states — the tree is too large. Instead we search to a fixed depth and use an evaluation function to estimate how good a non-terminal state is for MAX.

What is an Evaluation Function?

An evaluation function EVAL(s) estimates the utility of state s — it replaces the exact utility used in Minimax when we cut off the search early.

ValueMeaning
Large positiveState is very good for MAX
ZeroState is neutral / balanced
Large negativeState is very good for MIN

Properties of a Good Evaluation Function

  • Must agree with utility function at terminal states
  • Must be fast to compute — called millions of times per move
  • Should accurately reflect the true chance of winning
  • Based on features of the state (material count, piece position, control of center etc.)

Example — Chess Evaluation

  EVAL(s) = Σ w_i × f_i(s)

  Features (f_i):    Weights (w_i):
  ─────────────────────────────────
  Pawn count         +1 per pawn advantage
  Knight/Bishop      +3 per piece advantage
  Rook               +5 per piece advantage
  Queen              +9 per piece advantage
  King safety        large weight

Cutoff Test

Instead of a terminal test, we use a cutoff test to decide when to stop the search and apply the evaluation function:

  • Simple cutoff: stop at a fixed depth d
  • Smarter cutoff: use quiescence search — continue until the position is stable (no captures or checks)

Minimax vs Alpha-Beta — Quick Comparison

PropertyMinimaxAlpha-Beta Pruning
Result Optimal Identical to Minimax
Nodes explored O(bm) O(bm/2) best case
Pruning ✗ None ✓ Yes — skips irrelevant branches
Extra parameters None α and β values
Move ordering matters? ✗ No ✓ Yes — better ordering = more pruning
Practical use Too slow for real games Used in real chess engines

GATE Tips

  • Minimax — MAX maximizes, MIN minimizes. Back up values from leaves to root.
  • Time complexity of Minimax = O(bm). Space = O(b·m).
  • Alpha-Beta gives same result as Minimax — just faster.
  • α = best MAX can guarantee (starts -∞). β = best MIN can guarantee (starts +∞).
  • Prune when α ≥ β.
  • Best case Alpha-Beta = O(bm/2) with perfect move ordering.
  • Evaluation function replaces utility when search is cut off before terminal states.
  • Zero-sum game — one player's gain = other player's loss. Total utility always = 0.
  • In GATE questions, always calculate minimax values bottom-up from leaves to root.

Q1 In Minimax, what does the MAX player do at each node?

  1. Picks the child with minimum utility
  2. Picks the child with maximum utility
  3. Picks a random child
  4. Picks the child closest to the goal
Show Answer

Answer: B — Picks the child with maximum utility

MAX wants to maximize their advantage. MIN picks the minimum.

Q2 What is the time complexity of the Minimax algorithm?

  1. O(bm/2)
  2. O(b · m)
  3. O(bm)
  4. O(mb)
Show Answer

Answer: C — O(bm)

b = branching factor, m = maximum depth. Minimax explores the entire game tree.

Q3 Alpha-Beta Pruning returns a result that is:

  1. Always better than Minimax
  2. Always worse than Minimax
  3. Identical to Minimax
  4. An approximation of Minimax
Show Answer

Answer: C — Identical to Minimax

Alpha-Beta is an optimization — it prunes branches that cannot affect the result, so the final answer is exactly the same.

Q4 In Alpha-Beta Pruning, pruning occurs when:

  1. α < β
  2. α > β
  3. α ≥ β
  4. α = 0
Show Answer

Answer: C — α ≥ β

When alpha (MAX's best) ≥ beta (MIN's best), the current branch cannot improve the result and is pruned.

Q5 What is the best-case time complexity of Alpha-Beta Pruning?

  1. O(bm)
  2. O(bm/2)
  3. O(b · m)
  4. O(log bm)
Show Answer

Answer: B — O(bm/2)

With perfect move ordering, Alpha-Beta effectively doubles the search depth compared to Minimax.

Q7 An evaluation function in game search is used when:

  1. The game has no terminal states
  2. The search is cut off before reaching terminal states
  3. Alpha-Beta pruning fails
  4. The branching factor is 1
Show Answer

Answer: B — Search is cut off before terminal states

When the game tree is too large to search completely, we cut off at a fixed depth and use an evaluation function to estimate the utility.

Q8 Which of the following is TRUE about a zero-sum game?

  1. Both players can win simultaneously
  2. One player's gain equals the other player's loss
  3. The total utility is always positive
  4. Both players cooperate to maximize total utility
Show Answer

Answer: B — One player's gain equals the other player's loss

In zero-sum games, the sum of utilities for all players is always zero. What MAX gains, MIN loses.
