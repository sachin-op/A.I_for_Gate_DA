Uniform Cost Search (UCS)

Uninformed Search GATE DA 📖 ~9 min read

Uniform Cost Search (UCS) is an uninformed search algorithm that finds the minimum cost path to the goal. Unlike BFS which expands by depth level, UCS expands the node with the lowest path cost g(n) using a Priority Queue.

Core Idea: Always expand the frontier node with the smallest cumulative path cost g(n). UCS is the uninformed version of Dijkstra's algorithm.

How UCS Works

  1. Insert the start node with cost g = 0 into a min-priority queue.
  2. Remove the node with the lowest g(n) from the queue.
  3. If it is the goal → return the solution.
  4. Otherwise → expand it and add children with updated costs g(child) = g(parent) + cost(edge).
  5. If a child is already in the frontier with higher cost → update its cost.
  6. Repeat until goal is found or queue is empty.

Data Structure Used

Min-Priority Queue — ordered by cumulative path cost g(n).

Key Formula

g(n) = total cost from start node to node n

Key Insight: BFS is a special case of UCS where all edge costs = 1. When costs are equal, UCS and BFS explore nodes in exactly the same order.

Condition for Completeness

UCS is complete only when every step cost ε > 0. If any step cost is 0 or negative:

  • Zero cost edges → UCS may loop on zero-cost cycles forever
  • Negative costs → UCS cannot guarantee finding the optimal path

For negative costs, use Bellman-Ford instead.

Advantages & Disadvantages

Advantages

  • Always optimal — finds minimum cost path (positive costs)
  • Complete when step costs are positive
  • Works correctly for weighted graphs unlike BFS

Disadvantages

  • High memory — stores all frontier nodes like BFS
  • Slow — explores in all directions, not just toward the goal
  • No heuristic to guide search — use A* for guided optimal search

GATE Tips

  • UCS uses a min-priority queue ordered by g(n).
  • UCS is complete and optimal when all step costs ε > 0.
  • BFS is a special case of UCS with all costs = 1.
  • UCS expands nodes in order of increasing path cost, not depth.
  • UCS is essentially Dijkstra's algorithm applied to AI search.
  • A* = UCS + heuristic h(n). When h(n) = 0, A* becomes UCS.
  • Time complexity notation: C* = optimal solution cost, ε = minimum step cost.
📝  Practice Questions

Q1 What data structure does UCS use?

  1. Stack (LIFO)
  2. Queue (FIFO)
  3. Min-Priority Queue
  4. Max-Priority Queue
Show Answer

Answer: C — Min-Priority Queue

UCS orders frontier nodes by cumulative path cost g(n) — lowest cost first.

Q2 UCS is optimal because:

  1. It explores all nodes at each depth before going deeper
  2. It always expands the node with the lowest cumulative cost g(n)
  3. It uses a heuristic to guide the search
  4. It avoids revisiting nodes
Show Answer

Answer: B

Expanding the minimum g(n) node first guarantees the first time we reach the goal, it is via the optimal path.

Q3 When does UCS become equivalent to BFS?

  1. When the branching factor b = 1
  2. When all step costs are equal
  3. When the depth d is very large
  4. When a heuristic is added
Show Answer

Answer: B — When all step costs are equal

With equal costs, g(n) is proportional to depth — so UCS and BFS expand nodes in the same order.

Q4 UCS may fail (not complete) when:

  1. The branching factor is too large
  2. Step costs include zeros (zero-cost cycles possible)
  3. The goal is at a very deep level
  4. The graph is undirected
Show Answer

Answer: B — Zero step costs

Zero-cost cycles can cause UCS to loop indefinitely without making progress.

Q5 What is the relationship between UCS and A*?

  1. A* is a special case of UCS with h(n) = 0
  2. UCS is a special case of A* with h(n) = 0
  3. They are completely different algorithms
  4. UCS is faster than A* always
Show Answer

Answer: B — UCS is A* with h(n) = 0

A* uses f(n) = g(n) + h(n). When h(n) = 0, f(n) = g(n) — which is exactly UCS.
